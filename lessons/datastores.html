DataStore: сохранение прогресса

Без сохранений игрок теряет всё при выходе. DataStore — облачное хранилище Roblox, где данные игроков живут между сессиями и серверами. Научимся сохранять надёжно, без потерь данных.

🎯 После урока ты сможешь:
  • включить DataStore в Studio;
  • загружать и сохранять данные через GetAsync, SetAsync, UpdateAsync;
  • обрабатывать ошибки через pcall;
  • сохранять при выходе и при выключении сервера.

Подготовка

  1. Опубликуй игру: File → Publish to Roblox. DataStore работает только у опубликованных игр.
  2. Открой Home → Game Settings → Security и включи Enable Studio Access to API Services.

Данные из Studio сохраняются в то же хранилище, что и у настоящих игроков. Для экспериментов используй отдельное имя хранилища, например "PlayerData_Test".

DataStore работает только на сервере, в Script. Клиент к нему доступа не имеет, и это правильно: иначе читеры записывали бы себе что угодно.

Основы

local DataStoreService = game:GetService("DataStoreService")
local store = DataStoreService:GetDataStore("PlayerData_v1")

-- Сохранить: ключ + значение
store:SetAsync("Player_12345", {coins = 100, level = 3})

-- Загрузить
local data = store:GetAsync("Player_12345")
print(data.coins) --> 100
  • Хранилище (DataStore) — как папка. У него есть имя.
  • Ключ — имя записи. Для игроков используй UserId: "Player_" .. player.UserId.
  • Значение — число, строка, boolean или таблица из них. Нельзя сохранить Instance, Vector3, Color3 напрямую. Их нужно перевести в числа.

pcall — защита от сбоев

DataStore — запрос по сети к серверам Roblox. Он может не пройти: перегрузка, лимиты, сбой. Если вызвать его напрямую и он упадёт, твой скрипт остановится с ошибкой. Поэтому все вызовы оборачивают в pcall («protected call»):

local success, result = pcall(function()
	return store:GetAsync("Player_12345")
end)

if success then
	print("Загружено:", result)       -- result = данные (или nil, если записи нет)
else
	warn("Ошибка загрузки:", result)  -- result = текст ошибки
end

pcall возвращает true и результат, если всё хорошо, или false и текст ошибки, если нет. Скрипт при этом не падает.

UpdateAsync — безопасное изменение

SetAsync просто перезаписывает. Если игрок одновременно оказался на двух серверах (например, быстро перешёл), один сервер может затереть данные другого. UpdateAsync читает текущее значение и даёт тебе его изменить:

pcall(function()
	store:UpdateAsync("Player_12345", function(oldData)
		oldData = oldData or {coins = 0}
		oldData.coins += 50
		return oldData          -- вернуть nil = отменить запись
	end)
end)

Для сохранения прогресса игрока рекомендуется UpdateAsync: он надёжнее при одновременных записях.

Полная система сохранений

Соберём рабочую систему: загрузка при входе, leaderstats, сохранение при выходе, при выключении сервера и автосохранение.

Explorer

    • DataManager
local Players = game:GetService("Players")
local DataStoreService = game:GetService("DataStoreService")
local store = DataStoreService:GetDataStore("PlayerData_v1")

local DEFAULT_DATA = {
	coins = 0,
	level = 1,
	inventory = {},
}

local sessionData = {}   -- [player] = таблица данных во время игры
local AUTOSAVE_INTERVAL = 120

local function getKey(player)
	return "Player_" .. player.UserId
end

-- Загрузка с несколькими попытками
local function loadData(player)
	for attempt = 1, 3 do
		local success, result = pcall(function()
			return store:GetAsync(getKey(player))
		end)
		if success then
			return true, result
		end
		warn(`Загрузка {player.Name}, попытка {attempt}: {result}`)
		task.wait(2)
	end
	return false, nil
end

local function saveData(player)
	local data = sessionData[player]
	if not data then return end  -- данные не загружены — НЕ сохраняем, чтобы не затереть

	local success, err = pcall(function()
		store:UpdateAsync(getKey(player), function()
			return data
		end)
	end)
	if not success then
		warn(`Не удалось сохранить {player.Name}: {err}`)
	end
end

local function setupLeaderstats(player, data)
	local leaderstats = Instance.new("Folder")
	leaderstats.Name = "leaderstats"

	local coins = Instance.new("IntValue")
	coins.Name = "Coins"
	coins.Value = data.coins
	coins.Parent = leaderstats

	local level = Instance.new("IntValue")
	level.Name = "Level"
	level.Value = data.level
	level.Parent = leaderstats

	-- leaderstats меняют другие скрипты — синхронизируем в sessionData
	coins.Changed:Connect(function(value) data.coins = value end)
	level.Changed:Connect(function(value) data.level = value end)

	leaderstats.Parent = player
end

Players.PlayerAdded:Connect(function(player)
	local success, saved = loadData(player)
	if not success then
		player:Kick("Не удалось загрузить данные. Перезайдите, пожалуйста.")
		return
	end

	-- Новый игрок → копия шаблона. Старый → дополним новыми полями, если они появились
	local data = table.clone(DEFAULT_DATA)
	data.inventory = {}
	if saved then
		for key, value in saved do
			data[key] = value
		end
	end

	sessionData[player] = data
	setupLeaderstats(player, data)
	print(`Данные {player.Name} загружены: {data.coins} монет`)
end)

Players.PlayerRemoving:Connect(function(player)
	saveData(player)
	sessionData[player] = nil
end)

-- Сервер выключается: сохраняем всех, пока есть время (до 30 секунд)
game:BindToClose(function()
	local pending = 0
	for _, player in Players:GetPlayers() do
		pending += 1
		task.spawn(function()      -- сохраняем всех параллельно
			saveData(player)
			pending -= 1
		end)
	end
	while pending > 0 do           -- и ждём, пока все сохранения закончатся
		task.wait()
	end
end)

-- Автосохранение на случай краша сервера
task.spawn(function()
	while true do
		task.wait(AUTOSAVE_INTERVAL)
		for _, player in Players:GetPlayers() do
			task.spawn(saveData, player)
		end
	end
end)

Разбор важных моментов

  • sessionData: во время игры работаем с таблицей в памяти, а не дёргаем DataStore на каждое изменение. У DataStore есть лимиты на количество запросов.
  • Если загрузка не удалась — кик, а не пустые данные. Иначе игрок поиграет «с нуля», выйдет, и пустые данные перезапишут его настоящий прогресс. Это самая частая причина «у меня пропал прогресс!».
  • BindToClose: когда сервер закрывается (последний игрок вышел, обновление игры), PlayerRemoving может не успеть. BindToClose даёт до 30 секунд на сохранение.
  • DEFAULT_DATA + слияние: если ты добавишь в игру новое поле (например, gems), у старых игроков оно появится со значением по умолчанию.

Что можно и нельзя сохранять

-- ❌ Нельзя: Instance, Vector3, Color3, CFrame
-- data.lastPosition = root.Position

-- ✅ Можно: переводим в числа
local pos = root.Position
data.lastPosition = {x = pos.X, y = pos.Y, z = pos.Z}

-- И обратно при загрузке
local p = data.lastPosition
local position = Vector3.new(p.x, p.y, p.z)

-- ✅ Инвентарь храним названиями, а не самими предметами
data.inventory = {"Sword", "Shield"}

Ограничения: значение до 4 МБ на ключ. Ключи у таблиц должны быть строками (словарь) или идти подряд с 1 (массив). Смешанные таблицы сохраняются неправильно.

OrderedDataStore — таблица лидеров

Для глобального топа (лучшие игроки за всё время) есть OrderedDataStore. Он хранит только числа, зато умеет сортировать:

local DataStoreService = game:GetService("DataStoreService")
local Players = game:GetService("Players")
local leaderboard = DataStoreService:GetOrderedDataStore("TopCoins_v1")

-- Записать результат игрока
local function submit(player, coins)
	pcall(function()
		leaderboard:SetAsync(tostring(player.UserId), coins)
	end)
end

-- Получить топ-10
local function printTop()
	local success, pages = pcall(function()
		return leaderboard:GetSortedAsync(false, 10)  -- false = по убыванию
	end)
	if not success then return end

	for rank, entry in pages:GetCurrentPage() do
		local name = "?"
		pcall(function()
			name = Players:GetNameFromUserIdAsync(tonumber(entry.key))
		end)
		print(`{rank}. {name} — {entry.value}`)
	end
end

Для больших проектов сообщество использует готовые модули сохранений: ProfileStore (преемник ProfileService) и DataStore2. Они решают блокировку сессий и другие сложные случаи. Сначала разберись с основами из этого урока, потом смотри на них.

🧠 Проверь себя

Зачем оборачивать GetAsync в pcall?

  1. Чтобы запрос шёл быстрее
  2. Так требует синтаксис
  3. Запрос может завершиться ошибкой, и без pcall скрипт упадёт
  4. Чтобы данные шифровались

Сетевые запросы ненадёжны, pcall перехватывает ошибку.

Загрузка данных не удалась. Что лучше сделать?

  1. Кикнуть игрока с просьбой перезайти и не сохранять его данные
  2. Дать игроку стартовые данные и сохранять их как обычно
  3. Ничего не делать
  4. Удалить запись в DataStore

Если сохранить «пустые» данные, они затрут настоящий прогресс игрока.

Что из этого можно сохранить в DataStore напрямую?

  1. Vector3.new(1, 2, 3)
  2. workspace.Sword
  3. Color3.new(1, 0, 0)
  4. {coins = 10, items = {"Sword"}}

Только простые значения и таблицы из них. Типы Roblox нужно переводить в числа.

Для чего нужен game:BindToClose?

  1. Чтобы игроки не могли выйти
  2. Чтобы успеть сохранить данные, когда сервер выключается
  3. Чтобы закрыть DataStore
  4. Чтобы закрыть GUI

При выключении сервера PlayerRemoving может не успеть отработать.

Какой ключ лучше использовать для данных игрока?

  1. player.Name
  2. player.DisplayName
  3. "Player_" .. player.UserId
  4. tostring(os.time())

UserId постоянный и уникальный.

📚 Задания

Задание 1 лёгкое

Сохраняй и загружай одно число: сколько раз игрок заходил в игру. При входе выведи: Ты зашёл уже N раз!

✅ Решение 
local Players = game:GetService("Players")
local store = game:GetService("DataStoreService"):GetDataStore("Visits_v1")

Players.PlayerAdded:Connect(function(player)
	local success, visits = pcall(function()
		return store:UpdateAsync("Player_" .. player.UserId, function(old)
			return (old or 0) + 1
		end)
	end)
	if success then
		print(`{player.Name}, ты зашёл уже {visits} раз!`)
	end
end)

UpdateAsync возвращает новое значение, поэтому загрузка и сохранение здесь одной операцией.

Задание 2 среднее

Возьми DataManager из урока и добавь сохранение инвентаря: при входе игрок получает в Backpack все инструменты из data.inventory (шаблоны лежат в ServerStorage.Tools). Добавь серверную функцию giveItem(player, name), которая выдаёт инструмент и записывает его в инвентарь.

✅ Решение (дополнение к DataManager) 
local ServerStorage = game:GetService("ServerStorage")
local toolsFolder = ServerStorage:WaitForChild("Tools")

local function giveTool(player, toolName)
	local template = toolsFolder:FindFirstChild(toolName)
	if template then
		template:Clone().Parent = player.Backpack
	end
end

local function giveItem(player, toolName)
	local data = sessionData[player]
	if not data then return end
	if table.find(data.inventory, toolName) then return end  -- уже есть
	table.insert(data.inventory, toolName)
	giveTool(player, toolName)
end

-- В PlayerAdded после загрузки данных:
-- инструменты в Backpack пропадают после смерти, поэтому выдаём при каждом спавне
player.CharacterAdded:Connect(function()
	for _, toolName in data.inventory do
		giveTool(player, toolName)
	end
end)

Задание 3 сложное

Сделай сохранение позиции: при выходе запоминай, где стоял игрок, а при следующем входе телепортируй его туда.

✅ Решение 
local Players = game:GetService("Players")
local store = game:GetService("DataStoreService"):GetDataStore("Positions_v1")

Players.PlayerAdded:Connect(function(player)
	local ok, saved = pcall(function()
		return store:GetAsync("Player_" .. player.UserId)
	end)

	player.CharacterAdded:Once(function(character)
		if ok and saved then
			task.wait(0.5)  -- даём персонажу загрузиться
			character:PivotTo(CFrame.new(saved.x, saved.y + 3, saved.z))
		end
	end)
end)

Players.PlayerRemoving:Connect(function(player)
	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	if not root then return end
	local p = root.Position
	pcall(function()
		store:SetAsync("Player_" .. player.UserId, {x = p.X, y = p.Y, z = p.Z})
	end)
end)
