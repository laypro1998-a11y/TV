RemoteEvent и RemoteFunction

Мост между клиентом и сервером. Без него не сделать ни магазин, ни способность, ни оружие. Разберём все направления и, главное, как сделать это безопасно.

🎯 После урока ты сможешь:
  • отправлять сообщения клиент → сервер и сервер → клиент;
  • использовать RemoteFunction, чтобы получать ответ;
  • правильно расположить Remote-объекты и скрипты;
  • проверять данные от клиента, чтобы защититься от читеров.

Где хранить RemoteEvent

Remote должен быть виден и серверу, и клиенту, значит, его место в ReplicatedStorage. Удобно собрать их в папку:

Explorer
  • ReplicatedStorage
    • Remotes
      • ClickRemote RemoteEvent
      • Notify RemoteEvent
      • GetShopData RemoteFunction
  • ServerScriptService
    • RemoteHandler
  • StarterGui
    • MainGui
      • ClientController

Создай их в Studio: ReplicatedStorage → ⊕ → Folder (назови Remotes) → внутрь ⊕ → RemoteEvent.

Направление 1: клиент → сервер

Клиент вызывает :FireServer(...), сервер слушает .OnServerEvent.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local remotes = ReplicatedStorage:WaitForChild("Remotes")
local clickRemote = remotes:WaitForChild("ClickRemote")

local button = script.Parent:WaitForChild("ClickButton")

button.Activated:Connect(function()
	clickRemote:FireServer()   -- «сервер, я кликнул!»
end)
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local clickRemote = ReplicatedStorage.Remotes.ClickRemote

clickRemote.OnServerEvent:Connect(function(player)
	-- player подставляет сам Roblox: это тот, кто вызвал FireServer
	player.leaderstats.Coins.Value += 1
end)

Первый аргумент OnServerEvent — всегда игрок, который отправил событие. Его подставляет Roblox, подделать его нельзя. Остальные аргументы — то, что передал клиент: FireServer("Sword", 3) → function(player, itemName, amount).

Направление 2: сервер → клиент

Сервер вызывает :FireClient(player, ...) для одного игрока или :FireAllClients(...) для всех. Клиент слушает .OnClientEvent.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Players = game:GetService("Players")
local notify = ReplicatedStorage.Remotes.Notify

Players.PlayerAdded:Connect(function(player)
	task.wait(3)
	notify:FireClient(player, `Добро пожаловать, {player.Name}!`)  -- только ему
	notify:FireAllClients(`{player.Name} присоединился к игре`)    -- всем
end)
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local notify = ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("Notify")

notify.OnClientEvent:Connect(function(message)
	-- на клиенте игрок НЕ передаётся первым аргументом
	print("Сообщение от сервера:", message)
end)

RemoteFunction — запрос с ответом

RemoteEvent — «отправил и забыл». RemoteFunction — «спросил и дождался ответа». Клиент вызывает :InvokeServer(...), на сервере выполняется функция OnServerInvoke, а её return возвращается клиенту.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local getShopData = ReplicatedStorage.Remotes.GetShopData

local PRICES = {Sword = 100, Shield = 150, Bow = 250}

-- Обрати внимание: присваивание (=), а не Connect
getShopData.OnServerInvoke = function(player)
	return {
		prices = PRICES,
		coins = player.leaderstats.Coins.Value,
	}
end
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local getShopData = ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("GetShopData")

local data = getShopData:InvokeServer()  -- скрипт ждёт ответа
print("Мои монеты:", data.coins)
for item, price in data.prices do
	print(item, price)
end

Никогда не используй InvokeClient (сервер спрашивает клиента и ждёт ответа). Читер может не ответить никогда, и серверный скрипт зависнет. Если серверу нужно что-то от клиента, используй два RemoteEvent.

Безопасность: проверяй всё

Читеры могут вызывать FireServer с любыми аргументами и сколько угодно раз. Представь, что каждый вызов прислал хакер. Посмотрим на плохой и хороший код.

❌ Уязвимый код

-- Клиент присылает, сколько монет добавить
addCoinsRemote.OnServerEvent:Connect(function(player, amount)
	player.leaderstats.Coins.Value += amount   -- читер пришлёт 999999999
end)

-- Клиент присылает цену товара
buyRemote.OnServerEvent:Connect(function(player, itemName, price)
	player.leaderstats.Coins.Value -= price    -- читер пришлёт price = -1000000
end)

✅ Защищённый код

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")
local Players = game:GetService("Players")

local buyRemote = ReplicatedStorage.Remotes.BuyItem
local itemsFolder = ServerStorage:WaitForChild("ShopItems")

local PRICES = {Sword = 100, Shield = 150}   -- цены знает только сервер
local COOLDOWN = 0.5
local lastRequest = {}

buyRemote.OnServerEvent:Connect(function(player, itemName)
	-- 1. Защита от спама
	local now = os.clock()
	if lastRequest[player] and now - lastRequest[player] < COOLDOWN then return end
	lastRequest[player] = now

	-- 2. Проверка типа данных
	if typeof(itemName) ~= "string" then return end

	-- 3. Проверка, что такой товар существует
	local price = PRICES[itemName]
	if not price then return end

	-- 4. Проверка баланса
	local coins = player.leaderstats.Coins
	if coins.Value < price then return end

	-- 5. Действие
	coins.Value -= price
	local item = itemsFolder:FindFirstChild(itemName)
	if item then
		item:Clone().Parent = player.Backpack
	end
end)

Players.PlayerRemoving:Connect(function(player)
	lastRequest[player] = nil
end)

Чек-лист проверки

  1. Тип: typeof(x) == "string", "number", "Instance"...
  2. Диапазон: число не NaN, не отрицательное, не огромное. Строка разумной длины.
  3. Существование: товар есть в таблице, объект ещё не удалён.
  4. Право: хватает денег, предмет принадлежит игроку, игрок жив.
  5. Дистанция: игрок рядом с объектом, с которым взаимодействует.
  6. Частота: кулдаун на запросы.

Числа проверяй так: if typeof(n) ~= "number" or n ~= n or n < 1 or n > 100 then return end. Проверка n ~= n ловит NaN: это единственное значение, которое не равно самому себе. Читеры любят присылать NaN.

UnreliableRemoteEvent

Для частых и неважных обновлений (позиция курсора, визуальные эффекты) есть UnreliableRemoteEvent: сообщения могут теряться, зато нагрузка на сеть меньше. Методы те же, что у RemoteEvent. Покупки и урон через него не делают.

🧠 Проверь себя

Клиент вызвал remote:FireServer("Sword"). Какие параметры получит функция в OnServerEvent?

  1. ("Sword")
  2. ("Sword", player)
  3. (player, "Sword")
  4. (remote, "Sword")

Первым всегда идёт игрок-отправитель, затем аргументы клиента.

Где должен лежать RemoteEvent?

  1. ReplicatedStorage
  2. ServerStorage
  3. ServerScriptService
  4. StarterGui

Его должны видеть обе стороны. ServerStorage и ServerScriptService клиенту недоступны.

Клиент отправляет BuyItem:FireServer("Sword", 100), где 100 — цена. Что не так?

  1. Нельзя передавать два аргумента
  2. Нужно использовать RemoteFunction
  3. Ничего, всё правильно
  4. Сервер не должен брать цену от клиента: читер пришлёт 0

Цена должна храниться на сервере. Клиент присылает только, что он хочет купить.

Как отправить сообщение сразу всем игрокам?

  1. remote:FireServer()
  2. remote:FireAllClients(...)
  3. remote:FireClient(all, ...)
  4. Цикл с InvokeClient

FireAllClients вызывается только на сервере.

Чем RemoteFunction отличается от RemoteEvent?

  1. Работает быстрее
  2. Работает только сервер → клиент
  3. Вызывающий ждёт и получает ответ (return)
  4. Не требует ReplicatedStorage

InvokeServer останавливает скрипт клиента, пока сервер не вернёт значение.

Задание 1 лёгкое

Сделай кнопку «Сменить цвет», которая перекрашивает деталь SharedPart в случайный цвет для всех игроков. Проверь на 2 игроках.

💡 Подсказка

Если покрасить в LocalScript, увидит только один. Значит, кнопка шлёт RemoteEvent, а красит сервер.

✅ Решение 
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local remote = ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("ChangeColor")

script.Parent:WaitForChild("ColorButton").Activated:Connect(function()
	remote:FireServer()
end)
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local remote = ReplicatedStorage.Remotes.ChangeColor
local part = workspace:WaitForChild("SharedPart")

remote.OnServerEvent:Connect(function(player)
	part.Color = Color3.fromHSV(math.random(), 1, 1)
	print(player.Name, "перекрасил деталь")
end)

Задание 2 среднее

Сделай систему объявлений: сервер каждые 30 секунд отправляет всем клиентам случайный совет из списка, а клиент показывает его на экране в TextLabel на 5 секунд.

✅ Решение 
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local announce = ReplicatedStorage.Remotes.Announce

local TIPS = {
	"Нажми Shift, чтобы бежать!",
	"Сундуки обновляются каждые 30 секунд",
	"Не наступай на лаву :)",
}

while true do
	task.wait(30)
	announce:FireAllClients(TIPS[math.random(1, #TIPS)])
end
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local announce = ReplicatedStorage:WaitForChild("Remotes"):WaitForChild("Announce")
local label = script.Parent:WaitForChild("TipLabel")
label.Visible = false

announce.OnClientEvent:Connect(function(text)
	label.Text = "💡 " .. text
	label.Visible = true
	task.wait(5)
	label.Visible = false
end)

Задание 3 сложное

Найди и исправь все уязвимости в этом серверном коде. Клиент отправляет, какой сундук он открыл:

openChest.OnServerEvent:Connect(function(player, chest, reward)
	player.leaderstats.Coins.Value += reward
	chest:Destroy()
end)
💡 Подсказка

Что, если reward = 1e9? Если chest — не сундук, а Baseplate? Если игрок за 500 студов от сундука? Если отправлять 100 раз в секунду?

✅ Решение 
local chestsFolder = workspace:WaitForChild("Chests")
local REWARD = 25          -- награду знает только сервер
local MAX_DISTANCE = 12

openChest.OnServerEvent:Connect(function(player, chest)
	-- это вообще объект, и он из папки сундуков?
	if typeof(chest) ~= "Instance" then return end
	if chest.Parent ~= chestsFolder then return end

	-- игрок рядом?
	local character = player.Character
	local root = character and character:FindFirstChild("HumanoidRootPart")
	if not root then return end
	if (root.Position - chest:GetPivot().Position).Magnitude > MAX_DISTANCE then return end

	-- сундук уже открыт? (Destroy убирает его из папки, повторно не пройдёт)
	chest:Destroy()
	player.leaderstats.Coins.Value += REWARD
end)

Награда теперь серверная, сундук проверяется по папке, дистанция проверена. Спам не поможет: сундук удаляется после первого открытия, и следующий запрос не пройдёт проверку Parent.
