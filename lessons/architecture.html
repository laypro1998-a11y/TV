Архитектура, безопасность и отладка

Ты знаешь все кирпичики. Теперь разберёмся, как строить из них большой проект так, чтобы через месяц в нём можно было разобраться, чтобы его не ломали читеры и чтобы игра не тормозила.

🎯 После урока ты сможешь:
  • организовать проект: точки входа, сервисы и контроллеры на модулях;
  • управлять множеством объектов через теги (CollectionService);
  • применять правила безопасности и производительности;
  • искать баги: точки останова, консоль разработчика, assert.

Проблема: «скрипт в каждой детали»

Начинающие кладут скрипт в каждую лаву, каждую монету и каждую дверь. Через месяц в игре 300 одинаковых скриптов. Нужно поменять урон лавы, и правку приходится делать 300 раз. Плюс каждый скрипт расходует ресурсы.

Профессиональный подход: мало скриптов, много модулей.

Точка входа

local ServerScriptService = game:GetService("ServerScriptService")
local servicesFolder = ServerScriptService:WaitForChild("Services")

-- 1. Загружаем все сервисы
local services = {}
for _, module in servicesFolder:GetChildren() do
	if module:IsA("ModuleScript") then
		services[module.Name] = require(module)
	end
end

-- 2. Инициализируем (Init — подготовка, без зависимостей друг от друга)
for name, service in services do
	if service.Init then
		service:Init(services)
	end
end

-- 3. Запускаем (Start — здесь сервисы могут обращаться друг к другу)
for name, service in services do
	if service.Start then
		task.spawn(service.Start, service)
	end
end

print("Сервер запущен. Сервисов:", #servicesFolder:GetChildren())

Пример сервиса

local CollectionService = game:GetService("CollectionService")

local HazardService = {}
local DAMAGE = 20
local cooldowns = {}

local function setupHazard(part)
	part.Touched:Connect(function(hit)
		local humanoid = hit.Parent:FindFirstChildOfClass("Humanoid")
		if not humanoid then return end
		if cooldowns[humanoid] then return end
		cooldowns[humanoid] = true
		humanoid:TakeDamage(DAMAGE)
		task.delay(0.5, function()
			cooldowns[humanoid] = nil
		end)
	end)
end

function HazardService:Init(services)
	self.services = services   -- ссылка на другие сервисы, если понадобятся
end

function HazardService:Start()
	for _, part in CollectionService:GetTagged("Hazard") do
		setupHazard(part)
	end
	CollectionService:GetInstanceAddedSignal("Hazard"):Connect(setupHazard)
end

return HazardService

CollectionService: теги вместо скриптов

Тег — это метка на объекте. Повесь тег Hazard на 300 деталей лавы, и один сервис выше будет обрабатывать их все, включая появившиеся позже.

Как поставить тег в Studio: выбери деталь → в Properties внизу раздел Tags → + → введи Hazard. Кодом:

local CollectionService = game:GetService("CollectionService")

local part = workspace.Lava
CollectionService:AddTag(part, "Hazard")      -- или part:AddTag("Hazard")
print(part:HasTag("Hazard"))                   --> true
print(#CollectionService:GetTagged("Hazard"))  -- сколько всего объектов с тегом

Теги + атрибуты = мощная связка. Тег говорит, что это (Hazard), атрибут — с какими параметрами (Damage = 50). Дизайнер уровней настраивает объекты в Studio, а код не меняется.

Безопасность: итоговый чек-лист

  1. Сервер — единственный источник правды. Деньги, урон, инвентарь, победы считает только он.
  2. Каждый RemoteEvent — потенциальная дыра. Проверяй тип, диапазон, существование, права, дистанцию, частоту.
  3. Клиент просит, а не сообщает результат. Не «я убил X», а «я выстрелил сюда».
  4. Секреты не кладут в ReplicatedStorage: промокоды, админ-логику, серверные модули.
  5. Проверяй физику персонажа, если она важна: скорость, телепорты, позиция при взаимодействии.
  6. Не делай Remote «на все случаи» вроде SetValue(object, property, value). Это прямой подарок читерам.
  7. Админ-команды проверяй по UserId на сервере, а не по нику или по наличию кнопки на клиенте.

Утечки памяти

Утечка — когда ненужные данные продолжают жить. Сервер работает часами, и утечки копятся до лагов и краша.

  • Таблицы с ключом-игроком чисть в PlayerRemoving.
  • Соединения с «вечными» событиями (RunService, сервисы) отключай, когда объект больше не нужен.
  • Удаляй объекты через Destroy(), а не просто Parent = nil: Destroy отключает все события объекта.

Отладка

print, warn, error, assert

print("Обычное сообщение")
warn("Предупреждение — жёлтое, легко найти глазами")

local function setLevel(level)
	assert(typeof(level) == "number", "level должен быть числом")  -- упадёт, если условие ложно
	if level < 1 then
		error("Уровень не может быть меньше 1")                    -- остановить с ошибкой
	end
end

Используй assert и error для «невозможных» ситуаций. Лучше упасть сразу с понятным сообщением, чем через 10 минут непонятно где.

Точки останова (Breakpoints)

  1. Кликни слева от номера строки в редакторе. Появится красная точка.
  2. Запусти игру. Когда код дойдёт до этой строки, игра замрёт.
  3. Наведи мышь на переменные, чтобы увидеть их значения. Окно Watch покажет выбранные переменные, Call Stack — кто вызвал функцию.
  4. Кнопки Step Into / Step Over выполняют код по одной строке.

Консоль разработчика

В запущенной игре (и в Studio, и на настоящем сервере) нажми F9. Там видны ошибки клиента и сервера, использование памяти, сетевая нагрузка. Это главный инструмент для поиска багов, которые появляются только в опубликованной игре.

Алгоритм поиска бага

  1. Посмотри Output: есть ли красная ошибка? Прочитай её целиком, там написаны скрипт и строка.
  2. Нет ошибки? Проверь, запустился ли скрипт: поставь print("старт") первой строкой. Если не вывелось, скрипт лежит не там или это не тот тип скрипта.
  3. Скрипт работает, но не так? Расставь print с переменными на каждом шаге и найди, где значение стало не таким, как ожидалось.
  4. Проверь, где выполняется код: сервер или клиент? Изменения клиента не видны серверу.
  5. Упрости: удали всё лишнее, пока баг не исчезнет. Последнее удалённое и есть причина.

🧠 Проверь себя

Как лучше сделать 200 одинаковых убивающих блоков?

  1. Скрипт в каждом блоке
  2. Тег на блоки и один серверный скрипт или сервис через CollectionService
  3. Один LocalScript
  4. Модуль в каждом блоке

Один код на все объекты: легко менять и дешевле по ресурсам.

Чем опасен RemoteEvent SetProperty(object, property, value)?

  1. Он медленный
  2. Он не работает на телефонах
  3. Ничем
  4. Читер сможет менять любые свойства любых объектов

Сервер становится послушным исполнителем любых команд клиента.

Скрипт не выдаёт ни ошибок, ни результатов. Что проверить первым?

  1. Запускается ли он вообще: правильные ли тип и место
  2. Переписать код заново
  3. Перезапустить Studio
  4. Включить --!strict

print первой строкой сразу покажет, работает ли скрипт.

📚 Задания

Задание 1 среднее

Переделай свои убивающие блоки и прыгалки из прошлых уроков: убери скрипты из деталей, повесь теги Hazard и JumpPad, а логику перенеси в один серверный скрипт через CollectionService. Сила прыжка должна браться из атрибута Power детали (по умолчанию 100).

✅ Решение 
local CollectionService = game:GetService("CollectionService")

local function onTagged(tag, setup)
	for _, obj in CollectionService:GetTagged(tag) do
		setup(obj)
	end
	CollectionService:GetInstanceAddedSignal(tag):Connect(setup)
end

onTagged("Hazard", function(part)
	part.Touched:Connect(function(hit)
		local humanoid = hit.Parent:FindFirstChildOfClass("Humanoid")
		if humanoid then
			humanoid.Health = 0
		end
	end)
end)

onTagged("JumpPad", function(part)
	part.Touched:Connect(function(hit)
		local root = hit.Parent:FindFirstChild("HumanoidRootPart")
		if root then
			local power = part:GetAttribute("Power") or 100
			root.AssemblyLinearVelocity = Vector3.new(0, power, 0)
		end
	end)
end)

Задание 2 сложное

Создай каркас проекта: ServerMain с загрузкой сервисов (Init/Start) и два сервиса: PlayerService (создаёт leaderstats) и RewardService (каждые 60 секунд даёт всем онлайн-игрокам +10 монет, обращаясь к PlayerService за функцией addCoins).

✅ Решение 
local Players = game:GetService("Players")
local PlayerService = {}

function PlayerService:Init()
	Players.PlayerAdded:Connect(function(player)
		local stats = Instance.new("Folder")
		stats.Name = "leaderstats"
		local coins = Instance.new("IntValue")
		coins.Name = "Coins"
		coins.Parent = stats
		stats.Parent = player
	end)
end

function PlayerService:addCoins(player, amount)
	local stats = player:FindFirstChild("leaderstats")
	if stats then
		stats.Coins.Value += amount
	end
end

return PlayerService
local Players = game:GetService("Players")
local RewardService = {}

function RewardService:Init(services)
	self.PlayerService = services.PlayerService
end

function RewardService:Start()
	while true do
		task.wait(60)
		for _, player in Players:GetPlayers() do
			self.PlayerService:addCoins(player, 10)
		end
	end
end

return RewardService

ServerMain — из примера в уроке. Start каждого сервиса запускается через task.spawn, поэтому бесконечный цикл в RewardService не блокирует остальные.

Задание 3 среднее

Найди проблемы в коде (их минимум 4):

local data = {}
game.Players.PlayerAdded:Connect(function(player)
	data[player] = {kills = 0}
	game:GetService("RunService").Heartbeat:Connect(function()
		player.PlayerGui.HUD.Kills.Text = data[player].kills
	end)
end)
game.ReplicatedStorage.AddKill.OnServerEvent:Connect(function(player, amount)
	data[player].kills += amount
end)
✅ Ответ
  1. data[player] не очищается при выходе: утечка памяти.
  2. Heartbeat-соединение не отключается, когда игрок выходит, и продолжит работать и падать с ошибками.
  3. Сервер обновляет UI каждый кадр. UI — работа клиента, и обновлять его нужно только при изменении.
  4. AddKill принимает число от клиента: читер пришлёт amount = 99999. Киллы должен засчитывать сервер при реальной смерти врага.
  5. Нет проверки типа amount (NaN, строка).
