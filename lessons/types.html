Типизация Luau

Главное отличие Luau от обычного Lua — система типов. Она находит ошибки до запуска игры, улучшает автодополнение и делает большой код понятным. В профессиональных студиях на Roblox типы используют повсеместно.

🎯 После урока ты сможешь:
  • включать строгий режим --!strict;
  • указывать типы переменных, параметров и возвращаемых значений;
  • объявлять свои типы через type;
  • использовать опциональные типы, объединения и приведение типов.

Режимы проверки

Первой строкой скрипта можно указать режим:

СтрокаЧто делает
--!nocheckПроверка типов выключена
--!nonstrictПо умолчанию. Проверяет только очевидные ошибки, неизвестное считает any
--!strictСтрогий режим: всё должно сходиться по типам

Ошибки типов Studio показывает подчёркиванием в редакторе и в окне Script Analysis (View → Script Analysis). На запуск игры они не влияют: это подсказки, а не ошибки выполнения.

Аннотации типов

--!strict

local coins: number = 100
local playerName: string = "Alex"
local isReady: boolean = false

local function addCoins(current: number, amount: number): number
	return current + amount
end

addCoins(coins, "50")   -- ⚠ Studio подчеркнёт: string не является number

Синтаксис: имя: тип для переменных и параметров и ): тип после скобок для возвращаемого значения.

Не нужно подписывать тип везде. Luau сам выводит его: в local coins = 100 он и так знает, что это number. Подписывай параметры функций и сложные структуры.

Типы Roblox

--!strict
local Players = game:GetService("Players")

local function healPlayer(player: Player, amount: number)
	local character = player.Character
	if not character then return end

	local humanoid = character:FindFirstChildOfClass("Humanoid")
	if humanoid then
		humanoid.Health += amount
	end
end

local part: Part = Instance.new("Part")
local position: Vector3 = Vector3.new(0, 10, 0)
local color: Color3 = Color3.fromRGB(255, 0, 0)

Все классы Roblox — это типы: Player, Model, BasePart, Humanoid, RemoteEvent и т.д.

Опциональные типы: ?

string? означает «строка или nil». Строгий режим заставит проверить на nil перед использованием, и это спасает от attempt to index nil:

--!strict
local function findTool(player: Player, name: string): Tool?
	local backpack = player:FindFirstChild("Backpack")
	if not backpack then return nil end
	local tool = backpack:FindFirstChild(name)
	if tool and tool:IsA("Tool") then
		return tool
	end
	return nil
end

local tool = findTool(player, "Sword")  -- player — какой-то игрок
-- tool.Name     ⚠ ошибка: tool может быть nil
if tool then
	print(tool.Name)  -- ✔ внутри проверки Luau знает, что tool — Tool
end

Свои типы: type

--!strict

export type ItemData = {
	name: string,
	price: number,
	damage: number?,              -- необязательное поле
	rarity: "Common" | "Rare" | "Legendary",  -- только одно из трёх значений
}

export type Inventory = {ItemData}           -- массив ItemData
export type PriceList = {[string]: number}   -- словарь: строка → число

return {}  -- модуль обязан что-то вернуть, хоть пустую таблицу

export делает тип доступным в других скриптах:

--!strict
local Types = require(game:GetService("ReplicatedStorage").Types)

local sword: Types.ItemData = {
	name = "Меч",
	price = 100,
	damage = 25,
	rarity = "Rare",
}

local broken: Types.ItemData = {
	name = "Щит",
	price = "дорого",   -- ⚠ string вместо number
	rarity = "Epic",    -- ⚠ такого варианта нет
}

Объединения и приведение

--!strict

-- Объединение: значение одного из типов
local function describe(value: number | string): string
	if typeof(value) == "number" then
		return `Число {value}`      -- здесь Luau знает: value — number
	end
	return `Строка "{value}"`       -- а здесь — string
end

-- Приведение типа через ::
-- Когда ты знаешь больше, чем анализатор
local part = workspace:WaitForChild("Door") :: BasePart
part.Transparency = 0.5

:: не проверяет и не преобразует ничего во время игры, а только говорит анализатору «поверь мне». Если там окажется не BasePart, ошибка всё равно будет, просто позже. Используй, когда уверен.

Функции как типы и обобщения

--!strict
local TableUtils = {}

-- Тип функции: принимает number, возвращает boolean
type Predicate = (number) -> boolean

function TableUtils.countIf(list: {number}, check: Predicate): number
	local count = 0
	for _, v in list do
		if check(v) then count += 1 end
	end
	return count
end

-- Обобщённая (generic) функция: T — «любой тип»
function TableUtils.last<T>(list: {T}): T?
	return list[#list]
end

return TableUtils
--!strict
local TableUtils = require(game:GetService("ReplicatedStorage").TableUtils)

print(TableUtils.countIf({5, 12, 8, 20}, function(n) return n > 10 end)) --> 2
local name = TableUtils.last({"a", "b", "c"})  -- Luau знает: name — string?

Типизированный класс

Продолжение урока про ООП, классы с типами:

--!strict
local Weapon = {}
Weapon.__index = Weapon

type WeaponData = {
	name: string,
	damage: number,
	cooldown: number,
	lastUsed: number,
}
export type Weapon = typeof(setmetatable({} :: WeaponData, Weapon))

function Weapon.new(name: string, damage: number, cooldown: number): Weapon
	local self = setmetatable({} :: WeaponData, Weapon)
	self.name = name
	self.damage = damage
	self.cooldown = cooldown
	self.lastUsed = 0
	return self
end

function Weapon.canAttack(self: Weapon): boolean
	return os.clock() - self.lastUsed >= self.cooldown
end

return Weapon

Теперь при вводе sword. Studio подскажет все поля и методы, а опечатки подчеркнёт.

🧠 Проверь себя

Что означает тип Player?

  1. Любой игрок
  2. Player или nil
  3. Массив игроков
  4. Неизвестный тип

Знак вопроса делает тип опциональным.

Что будет, если в --!strict передать строку в параметр типа number и запустить игру?

  1. Игра не запустится
  2. Studio автоматически исправит код
  3. Studio покажет предупреждение в редакторе, но игра запустится
  4. Строка превратится в число

Типы — подсказки анализатора. Код всё равно выполнится, и, возможно, упадёт уже при работе.

Как описать словарь «название предмета → цена»?

  1. {[string]: number}
  2. {string, number}
  3. {number}
  4. string -> number

{number} — массив чисел, {[K]: V} — словарь.

Что делает x :: BasePart?

  1. Превращает x в деталь
  2. Проверяет, что x — деталь, и кидает ошибку
  3. Создаёт новую деталь
  4. Говорит анализатору считать x деталью, без проверок во время игры

Это приведение типа только для анализатора.

Задание 1 лёгкое

Включи --!strict в одном из своих старых скриптов. Открой Script Analysis и исправь все предупреждения: добавь типы параметрам и проверки на nil.

✅ Что обычно всплывает
  • Параметры без типов в strict-режиме выводятся по использованию. Подпиши их явно.
  • FindFirstChild возвращает Instance?: нужна проверка if obj then.
  • Обращение к свойствам детали через FindFirstChild даёт Instance, у которого нет Transparency. Проверь через IsA("BasePart"), и Luau сузит тип.

Задание 2 среднее

Опиши тип QuestData (название, описание, награда-число, цель: тип "Kill" | "Collect" | "Visit", необязательное поле timeLimit). Сделай массив из 3 квестов и функцию getTotalReward(quests: {QuestData}): number.

✅ Решение 
--!strict
type QuestData = {
	title: string,
	description: string,
	reward: number,
	goal: "Kill" | "Collect" | "Visit",
	timeLimit: number?,
}

local quests: {QuestData} = {
	{title = "Охотник", description = "Победи 5 слизней", reward = 50, goal = "Kill"},
	{title = "Сборщик", description = "Собери 10 грибов", reward = 30, goal = "Collect", timeLimit = 120},
	{title = "Путник", description = "Дойди до маяка", reward = 20, goal = "Visit"},
}

local function getTotalReward(list: {QuestData}): number
	local total = 0
	for _, quest in list do
		total += quest.reward
	end
	return total
end

print(getTotalReward(quests)) --> 100

Задание 3 сложное

Напиши обобщённую функцию filter<T>(list: {T}, check: (T) -> boolean): {T}, которая возвращает новый массив подходящих элементов. Используй её для поиска всех BasePart в workspace:GetDescendants(), которые выше Y = 50.

✅ Решение 
--!strict
local function filter<T>(list: {T}, check: (T) -> boolean): {T}
	local result = {}
	for _, item in list do
		if check(item) then
			table.insert(result, item)
		end
	end
	return result
end

local high = filter(workspace:GetDescendants(), function(obj: Instance): boolean
	return obj:IsA("BasePart") and obj.Position.Y > 50
end)

print("Высоких деталей:", #high)
