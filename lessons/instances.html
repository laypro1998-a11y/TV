Объекты игры: Instance и иерархия

Всё, что есть в игре, — детали, скрипты, звуки, игроки, интерфейс — это объекты типа Instance. Научимся их находить, создавать, менять и удалять.

🎯 После урока ты сможешь:
  • понимать дерево объектов: Parent и Children;
  • правильно находить объекты: ., FindFirstChild, WaitForChild;
  • создавать, клонировать и удалять объекты;
  • использовать script.Parent и атрибуты.

Дерево объектов

Explorer показывает дерево. У каждого объекта есть родитель (Parent) и могут быть дети (Children).

Путь к окну: game.Workspace.House.Windows.Window1. Для Workspace есть короткое имя workspace, поэтому чаще пишут workspace.House.Windows.Window1.

local door = workspace.House.Door
print(door.Name)          --> Door
print(door.Parent.Name)   --> House
print(door.ClassName)     --> Part
print(door:GetFullName()) --> Workspace.House.Door

Три способа найти объект

СпособЕсли объекта нетКогда использовать
parent.NameОшибка, скрипт останавливаетсяОбъект точно есть (серверный скрипт и объект, созданный в Studio)
parent:FindFirstChild("Name")Возвращает nilОбъекта может не быть, и это нормально. Проверяем через if
parent:WaitForChild("Name")Ждёт, пока появитсяОбъект появится позже. Почти всегда в LocalScript, а также для объектов, создаваемых другими скриптами
-- На клиенте объекты загружаются по сети, поэтому ждём их
local house = workspace:WaitForChild("House")
local door = house:WaitForChild("Door")

-- Ищем то, чего может и не быть
local key = house:FindFirstChild("Key")
if key then
	print("В доме лежит ключ!")
end

Если WaitForChild ждёт больше 5 секунд, в Output появится жёлтое Infinite yield possible on .... Почти всегда это опечатка в имени или неправильный путь.

Почему точка иногда не работает? Если у объекта есть свойство с тем же именем, что и ребёнок, точка вернёт свойство. Например, деталь с именем Size внутри модели не найти через model.Size. Используй FindFirstChild, если имя совпадает со свойством или содержит пробелы.

script.Parent — объект рядом со скриптом

Внутри скрипта есть переменная script — сам скрипт. А script.Parent — тот, внутри кого он лежит. Так делают «самостоятельные» объекты: скрипт работает с тем, куда его положили.

Explorer
  • Workspace
    • SpinningPart
      • Spin
local part = script.Parent  -- деталь, в которой лежит скрипт
part.Anchored = true

while true do
	part.CFrame = part.CFrame * CFrame.Angles(0, math.rad(3), 0) -- поворот на 3°
	task.wait()
end

Скопируй эту деталь вместе со скриптом 10 раз, и все 10 будут вращаться. Такие скрипты удобны для простых вещей, но в больших играх так плодить скрипты не стоит. В уроке про архитектуру покажем, как управлять сотней объектов одним скриптом.

Создание объектов: Instance.new

local part = Instance.new("Part")    -- создали, но он ещё «нигде»
part.Name = "Platform"
part.Size = Vector3.new(10, 1, 10)
part.Position = Vector3.new(0, 10, 0)
part.Anchored = true
part.BrickColor = BrickColor.new("Cyan")
part.Parent = workspace              -- теперь появился в мире

Назначай Parent последним, после всех свойств. Объект появляется в мире один раз и уже настроенным. Так быстрее и без «мерцания».

Создавать можно что угодно: "Part", "Folder", "Model", "PointLight", "Fire", "Sound", "IntValue"...

local fire = Instance.new("Fire")
fire.Size = 8
fire.Parent = workspace.Platform  -- огонь на нашей платформе

local light = Instance.new("PointLight")
light.Range = 20
light.Color = Color3.fromRGB(255, 150, 50)
light.Parent = workspace.Platform

Clone и Destroy

Обычно сложные объекты (оружие, мобов, сундуки) не создают кодом по деталям. Их собирают в Studio, кладут в ServerStorage как шаблон и клонируют:

Explorer
  • ServerStorage
    • Chest — шаблон сундука
  • ServerScriptService
    • ChestSpawner
local ServerStorage = game:GetService("ServerStorage")
local chestTemplate = ServerStorage:WaitForChild("Chest")

for i = 1, 5 do
	local chest = chestTemplate:Clone()
	chest:PivotTo(CFrame.new(i * 10, 3, 0))   -- переместить модель целиком
	chest.Parent = workspace
	task.wait(1)
end

task.wait(5)
-- Удалить все сундуки с карты
for _, obj in workspace:GetChildren() do
	if obj.Name == "Chest" then
		obj:Destroy()
	end
end

Destroy() удаляет объект и всех его детей навсегда. После Destroy с объектом больше ничего не сделать.

IsA — проверка класса

for _, obj in workspace:GetDescendants() do
	if obj:IsA("BasePart") then  -- Part, MeshPart, WedgePart, ...
		obj.Material = Enum.Material.Wood
	end
end

IsA учитывает «родство» классов: IsA("BasePart") вернёт true и для Part, и для MeshPart. Проверка obj.ClassName == "Part" строже.

Атрибуты — свои свойства

Хочешь дать двери свойство IsLocked или мечу Damage? Используй атрибуты. Их можно добавить в окне Properties (внизу, кнопка Add Attribute) или кодом:

local door = workspace.House.Door
door:SetAttribute("IsLocked", true)
door:SetAttribute("KeyColor", "Red")

print(door:GetAttribute("IsLocked"))  --> true

-- Реагировать на изменение атрибута
door:GetAttributeChangedSignal("IsLocked"):Connect(function()
	print("Замок теперь:", door:GetAttribute("IsLocked"))
end)

Атрибуты видны в Properties, реплицируются клиентам и удобны для настройки объектов без правки кода.

🧠 Проверь себя

LocalScript падает с ошибкой Door is not a valid member of Workspace, хотя дверь есть. Как исправить?

  1. Переместить дверь в ServerStorage
  2. Использовать FindFirstChild
  3. Использовать workspace:WaitForChild("Door")
  4. Переименовать дверь

Клиенту дверь ещё не успела загрузиться. WaitForChild подождёт её.

Почему Parent лучше назначать последним?

  1. Объект появится в мире уже полностью настроенным
  2. Иначе объект не создастся
  3. Иначе будет ошибка
  4. Так требует синтаксис Luau

Работать будет и так, но назначать Parent последним быстрее и правильнее.

Где хранить шаблон моба, которого сервер будет клонировать?

  1. StarterGui
  2. Workspace
  3. StarterPlayerScripts
  4. ServerStorage

ServerStorage недоступен клиентам и не отображается в мире. Идеально для шаблонов.

Что такое script.Parent?

  1. Главный скрипт игры
  2. Объект, внутри которого лежит этот скрипт
  3. Сервис ServerScriptService
  4. Игрок, запустивший скрипт

script — сам скрипт, Parent — его родитель в дереве.

📚 Задания

Задание 1 лёгкое

Положи Script прямо в деталь в Workspace. Скрипт должен через script.Parent добавить в деталь огонь (Fire) и свет (PointLight).

✅ Решение 
local part = script.Parent

local fire = Instance.new("Fire")
fire.Parent = part

local light = Instance.new("PointLight")
light.Brightness = 3
light.Range = 16
light.Parent = part

Задание 2 среднее

Собери в Studio простую модель «дерево» (ствол + крона), сгруппируй (Ctrl+G), назови Tree и положи в ServerStorage. Напиши скрипт, который сажает 20 деревьев в случайных точках от −100 до 100 по X и Z.

💡 Подсказка

У модели должна быть настроена опорная точка (Pivot). Перемещай её через tree:PivotTo(CFrame.new(x, 0, z)).

✅ Решение 
local ServerStorage = game:GetService("ServerStorage")
local template = ServerStorage:WaitForChild("Tree")

local forest = Instance.new("Folder")
forest.Name = "Forest"
forest.Parent = workspace

for i = 1, 20 do
	local tree = template:Clone()
	local x = math.random(-100, 100)
	local z = math.random(-100, 100)
	tree:PivotTo(CFrame.new(x, 0, z))
	tree.Parent = forest
end

Задание 3 сложное

Сделай несколько дверей с атрибутом IsLocked (true или false) в папке Doors. Скрипт должен перебрать двери: запертые сделать красными и твёрдыми, открытые — зелёными, полупрозрачными и проходимыми. Бонус: обновляй вид двери, когда меняется её атрибут (проверь, поменяв атрибут во время Play в Properties на сервере).

✅ Решение 
local doors = workspace:WaitForChild("Doors")

local function updateDoor(door)
	local locked = door:GetAttribute("IsLocked")
	if locked then
		door.BrickColor = BrickColor.new("Really red")
		door.Transparency = 0
		door.CanCollide = true
	else
		door.BrickColor = BrickColor.new("Lime green")
		door.Transparency = 0.6
		door.CanCollide = false
	end
end

for _, door in doors:GetChildren() do
	updateDoor(door)
	door:GetAttributeChangedSignal("IsLocked"):Connect(function()
		updateDoor(door)
	end)
end
