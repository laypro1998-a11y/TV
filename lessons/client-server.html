Клиент и сервер: кто что видит

Ты уже знаешь, что Script работает на сервере, а LocalScript на клиенте. Теперь разберёмся глубже: как данные путешествуют между ними, кто чему «хозяин» и почему это главная защита от читеров.

🎯 После урока ты сможешь:
  • объяснить, что такое репликация;
  • предсказать, увидят ли другие игроки изменение;
  • понимать исключения: персонаж и сетевой владелец;
  • знать главное правило безопасности.

Репликация

Репликация — автоматическое копирование изменений по сети. Roblox делает её сам, но только в одну сторону:

Кто меняетКуда уходит изменение
📜 Сервер меняет объект в Workspace, ReplicatedStorage, Players...✔ Всем клиентам автоматически
🖥️ Клиент меняет объект✘ Никуда. Остаётся только у этого клиента

Эту защиту раньше называли FilteringEnabled. Сейчас она включена всегда, отключить нельзя.

Эксперимент

Запусти тест на 2 игрока (Test → Clients and Servers). Сделай в Workspace деталь Wall и два скрипта:

task.wait(5)
workspace.Wall.BrickColor = BrickColor.new("Really blue")
print("Сервер покрасил стену в синий")
local Players = game:GetService("Players")
local wall = workspace:WaitForChild("Wall")

if Players.LocalPlayer.Name == "Player1" then
	wall.BrickColor = BrickColor.new("Really red")
	print("Клиент Player1 покрасил стену в красный")
end

Результат:

  • Сразу после запуска: у Player1 стена красная, у Player2 и на сервере серая.
  • Через 5 секунд сервер красит в синий. Это изменение долетает до всех, и красный цвет у Player1 тоже перезаписывается.

Что видит клиент, а что нет

МестоСерверКлиент
Workspace✔✔ (копия)
ReplicatedStorage, ReplicatedFirst✔✔ (копия)
ServerScriptService, ServerStorage✔✘ Пусто: клиент даже не знает, что там лежит
Players › Player › PlayerGuiВидитТолько свой
Players › Player › PlayerScripts✘Только свои

Поэтому секретный код (проверка покупок, выдача наград) и ценные шаблоны (оружие для админов) храни в ServerScriptService и ServerStorage. Всё, что лежит в ReplicatedStorage и Workspace, читер может скопировать.

Исключения: что клиент всё-таки контролирует

1. Свой персонаж

Чтобы движение не тормозило, Roblox доверяет клиенту физику его персонажа. Ты нажимаешь W, персонаж идёт сразу, а сервер получает позицию от клиента. Поэтому:

  • WalkSpeed, изменённый на клиенте, действует: персонаж реально побежит быстрее (и все это увидят);
  • анимации, запущенные LocalScript на своём персонаже, видны всем;
  • отсюда и большинство читов на скорость и полёты. Сервер должен проверять, не двигается ли игрок слишком быстро.

2. Сетевой владелец (Network Ownership)

Незакреплённые детали рядом с игроком Roblox может отдать на «просчёт» этому клиенту, чтобы физика была плавной. Клиент-владелец может двигать такие детали. Для важных объектов сервер может забрать владение:

local ball = workspace:WaitForChild("Ball")
ball:SetNetworkOwner(nil)  -- nil = физику считает только сервер

3. Звуки и некоторые эффекты

Звук, запущенный на клиенте, слышит только этот игрок, но звуки внутри своего персонажа реплицируются. Помни это, если «звук слышен у всех», хотя ты играл его из LocalScript.

Как же клиенту что-то изменить?

Клиент не может менять общий мир, но может попросить сервер. Для этого есть специальные объекты: RemoteEvent и RemoteFunction (отдельный урок).

[Клиент] Игрок нажал «Купить меч»
    │  remote:FireServer("Sword")
    ▼
[Сервер] Проверяет: хватает ли денег? Существует ли меч?
    │  Списывает монеты, кладёт меч в Backpack
    ▼
[Все клиенты] Видят обновлённые монеты (репликация)

Главное правило безопасности

Никогда не доверяй клиенту. Всё, что приходит с клиента, читер может подделать: любые числа, любые названия, любую частоту запросов. Клиент может только просить, а решает всегда сервер.

❌ Плохо✅ Хорошо
Клиент: «Дай мне 100 монет»Клиент: «Я собрал монету №5». Сервер проверяет, что монета существует и игрок рядом
Клиент: «Я нанёс 50 урона игроку X»Клиент: «Я выстрелил в этом направлении». Сервер сам считает попадание и урон
Клиент: «Купи меч за 0 монет»Клиент: «Хочу купить меч». Цену сервер берёт из своего конфига

🧠 Проверь себя

Сервер изменил Transparency детали в Workspace. Кто это увидит?

  1. Только сервер
  2. Все игроки
  3. Только тот, кто ближе всех
  4. Никто, нужен RemoteEvent

Изменения на сервере реплицируются всем клиентам автоматически.

Что клиент увидит в ServerStorage?

  1. Всё содержимое
  2. Только модели
  3. Только модули
  4. Ничего

Содержимое ServerStorage и ServerScriptService не отправляется клиентам.

LocalScript поставил WalkSpeed = 100 своему персонажу. Что будет?

  1. Персонаж реально побежит быстрее
  2. Ничего: клиент не может это менять
  3. Ошибка в Output
  4. Изменится только анимация

Физикой своего персонажа управляет клиент. Поэтому скорость нужно проверять на сервере.

Как правильно сделать покупку?

  1. Клиент сам списывает монеты в leaderstats
  2. Клиент отправляет цену, сервер списывает её
  3. Клиент отправляет название товара, сервер берёт цену из своих данных и проверяет баланс
  4. Сервер выдаёт товар любому, кто попросит

Клиент только просит. Цену, баланс и наличие товара проверяет сервер.

📚 Задания

Задание 1 лёгкое

Повтори эксперимент с покраской стены на 2 игроках. Затем поменяй LocalScript, чтобы он удалял стену (Destroy). Пройдёт ли Player1 сквозь стену? Видит ли Player2, что стены нет у Player1?

✅ Ответ

У Player1 стены нет, и он пройдёт (его персонажа считает его клиент). Player2 и сервер стену видят. Player2 будет казаться, что Player1 прошёл сквозь стену. Так работают «noclip»-читы, поэтому важные барьеры проверяют на сервере.

Задание 2 среднее

Для каждой ситуации ответь, сработает ли она и увидят ли её другие игроки:

  1. LocalScript меняет player.leaderstats.Coins.Value.
  2. LocalScript создаёт Part в Workspace.
  3. Script создаёт Part в Workspace.
  4. LocalScript проигрывает анимацию танца на своём персонаже.
  5. LocalScript делает require модуля из ServerStorage.
✅ Ответ
  1. Изменится только у этого игрока, сервер и остальные не увидят.
  2. Деталь будет только у этого игрока.
  3. Увидят все.
  4. Увидят все: анимации своего персонажа реплицируются.
  5. Не сработает: клиент не видит ServerStorage, и WaitForChild будет ждать вечно.

Задание 3 среднее

Напиши серверный «античит скорости»: раз в секунду проверяй расстояние, на которое сместился HumanoidRootPart каждого игрока. Если больше 60 студов за секунду, выводи warn с ником (и, например, телепортируй обратно).

✅ Решение 
local Players = game:GetService("Players")
local MAX_DISTANCE_PER_SECOND = 60
local lastPositions = {}

while true do
	task.wait(1)
	for _, player in Players:GetPlayers() do
		local character = player.Character
		local root = character and character:FindFirstChild("HumanoidRootPart")
		if root then
			local last = lastPositions[player]
			if last and (root.Position - last).Magnitude > MAX_DISTANCE_PER_SECOND then
				warn(player.Name, "двигается подозрительно быстро!")
				character:PivotTo(CFrame.new(last))
			end
			lastPositions[player] = root.Position
		end
	end
end

Это учебный пример. В реальной игре учитывай падение, телепорты самой игры и прыжки с батутов, иначе пострадают честные игроки. Ещё нужно чистить lastPositions в PlayerRemoving.
